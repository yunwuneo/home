# Echo 聊天功能升级

保留唯一的 Echo 和原生 SwiftUI 客户端。Web 与 iOS 的话题、模型、MCP、指令、附件及记忆均由同一服务端管理。

## 使用

运行 `pnpm dev`，进入聊天 → 聊天设置。在模型页添加服务商（Base URL 包含 `/v1`），保存并获取模型，分别选择对话、记忆提取和向量模型。记忆模型可沿用对话模型。密钥存储在服务端 AES-256-GCM 加密配置中，读取配置不会返回密钥。

- **话题**：新建、切换、改名、删除、独立历史和模型选择；跨话题共享长期记忆。旧消息归入「和 Echo 的日常」。删除话题保留已提取的长期记忆，遗忘需在手记中操作。
- **模型**：多个服务商、拉取列表、收藏、不同功能选用不同模型。设置完成后两端共用。原设置页保留旧单模型连接兼容，新功能使用「聊天设置」。
- **MCP**：官方 SDK 支持 Streamable HTTP、SSE、服务端 stdio；可测试连接、列出工具，模型可多轮调用，消息下显示工具结果。stdio 命令的配置与变更仅限服务器电脑。两端话题设置可以限定工具范围。界面支持 Authorization 认证；其他 headers 和 env 可通过配置 API 写入，读取时隐藏。
- **指令**：全局或指定话题的模板、开关；支持 `{{user}}`、`{{assistant}}`、`{{date}}`、`{{topic}}`。
- **附件**：PNG/JPEG/WebP、PDF、DOCX、TXT/Markdown/CSV/JSON。最多 6 个、每个 10 MB。文档提取前 4 万字符，超出部分明确提示。扫描 PDF 无文字时提示转为照片。图片需要支持视觉的对话模型。iOS 支持系统相机、照片选择器、文件选择器和鉴权下载预览。
- **记忆**：默认使用真实 LLM 自动提取；手动提取、编辑、置顶、遗忘；真实 embeddings、模型/文本指纹失效检查、向量与关键词混合召回。回答展示本次记忆及来源。生成失败不提交聊天或提取结果；纠正/遗忘排除关联旧消息，避免再次把过期事实带回提示词。
- **语音**：设备语音识别、设备朗读；可单独配置兼容 `/audio/transcriptions` 和 `/audio/speech` 的云端服务商与模型。无云端配置时明确使用设备语音。支持录音转文字后编辑发送、朗读/停止，不包含实时通话。

附件内容本次发送会提供给模型；聊天历史保留附件引用。长期记忆来源只取用户文字陈述，文档中的文字不会自动当作用户画像。

## 测试

`pnpm test` 覆盖服务端回归、配置脱敏与持久化、话题隔离、失败原子性、向量检索、遗忘、附件，以及三种 MCP 传输。

真实验收必须使用独立数据目录，避免污染个人存档：

```sh
HOST=127.0.0.1 PORT=5187 ECHO_DATA_DIR=/tmp/echo-chat-acceptance node server/index.mjs --production
# 在另一个终端设置 ECHO_AI_URL 和 ECHO_AI_KEY，再执行：
node scripts/chat-live-check.mjs
node scripts/chat-browser-check.mjs
```

实时检查脚本会创建测试话题、记忆和附件，并调用模型及 embeddings。结果和截图位于 `artifacts/chat/`（不进入版本库）。

iOS 的 `ChatFeaturesUITests` 连接同一 5187 验收服务，运行设置/附件入口检查及真实跨话题记忆问答。相机和麦克风的物理采集需要真机验收；模拟器入口截图不能代替真机采集。
