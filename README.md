# 和 Echo 的家

一个本地优先的共同生活游戏。你和 25 岁的 Echo 刚开始在一间清新日式小家里生活，关系通过日常陪伴、神态、对话和共同回忆逐渐发展。

## 聊天升级

聊天现已支持独立话题、多服务商模型管理、MCP 工具、指令模板、照片与文件、LLM 记忆提取和真实向量召回，以及设备/云端语音服务。iOS 与 Web 通过服务端同步。见 [使用说明](docs/CHAT_UPGRADE.md) 与 [逐项验收记录](docs/CHAT_ACCEPTANCE.md)。

## 运行

需要 Node.js 22.13+（推荐 Node.js 24）和 pnpm。项目使用 Node 内置 SQLite。

```sh
pnpm install
pnpm dev
```

开发服务会监听 `server/` 和 `shared/` 的修改并自动重启，避免前端已经热更新、后端却仍使用旧接口；不会监听 Vite 自动生成的临时文件。修改后端时请使用 `pnpm dev`；直接运行 `node server/index.mjs` 的服务需要手动重启。手机应继续使用同一个局域网端口。目录监听适用于 Windows/macOS；Linux 开发可直接运行 `node server/index.mjs`，修改后端后手动重启。

默认监听 `0.0.0.0:5173`，本机使用 `http://127.0.0.1:5173`，局域网设备使用终端输出的 LAN 地址。当前电脑的以太网地址为 `http://192.168.31.206:5173`；设备须在可互通的局域网中。如果端口已占用，服务端会尝试接下来的端口。当前开发机器也可以直接运行 `node server/index.mjs`，依赖已经安装。

局域网设备第一次访问需要配对：在服务器电脑打开本机地址，进入设置，点击“生成配对码”，然后在手机上输入。配对码十分钟有效且只能使用一次；设备会话保留七天，重启服务不会丢失。手机设置中可以“断开此设备”。未配对的设备不能读取对话、存档、设置，也不能调用游戏操作接口。

当前 Windows 有阻止 Node 在公用网络入站的既有规则。`scripts/configure-lan-firewall.ps1` 是针对这台电脑准备的管理员脚本：仅为以太网本地子网放行 Node 的 TCP 5173，原规则继续阻止其他 TCP 端口，UDP 规则不变。脚本需要 Windows 管理员确认；加 `-Restore` 可移除该例外并恢复原来的 TCP 阻止范围。它引用了这台电脑已检查过的规则标识，不应直接用于其他电脑。

```sh
pnpm build
pnpm start
pnpm test
pnpm test:browser
```

`test:browser` 会启动独立的临时存档与服务端，使用已安装的 Chrome 完成桌面、手机横竖屏、3D 像素、视角、聊天、回忆、设置与活动测试，截图在 `artifacts/`。不会使用你的 API 或实际存档。

启动本地服务后，`pnpm test:activities` 使用浏览器内的测试状态检查八项活动的前、中、后期动作、桌面和手机画面、单人活动、暂停与取消，截图保存在 `artifacts/activities/`。不会改动实际存档；可用 `ECHO_VISUAL_URL` 指定预览地址，也可以运行 `node scripts/activity-check.mjs cook tea` 仅复查指定活动。

`pnpm test:city` 验证生活地图、家具近景、六处场景、出行过渡和失败恢复，以及桌面、手机横竖屏与减少动态效果偏好，截图保存在 `artifacts/city/`。通过拦截请求使用独立测试状态，不修改实际存档，也可用 `ECHO_VISUAL_URL` 指定地址。

## 已实现

### 聊天、记忆与相处

- 聊天支持真实流式接收、引用回复、会话内草稿、记录搜索和失败重试。相同发送编号重试不会重复调用模型或重复落档；模型回复未完整接收时不写入半条回复。
- 模型会结合当前地点、心情、关系阶段、正在玩的游戏、最近 40 条有效消息和最多 14 条相关长期记忆回答。支持普通 Chat Completions 的服务可在设置中关闭“逐段接收回复”。
- 自动记录明确说出的喜好、生日、生活信息、过敏、边界与约定；同一喜好的正反变化会更新原记录。自动识别采用保守的中文规则，不保证理解所有表达，复杂事实可以手动记录。
- 回忆手记支持分类、全文搜索、手动新增、置顶、编辑与遗忘。记忆不会再因超过 150 条而丢失。修改或遗忘会排除关联的旧聊天上下文，历史界面仍保留原对话；用户主动再次提起的内容可以重新记录。
- “一起玩”中有牵手、拥抱、听心事和夸赞，以及连续回应选项。可以在聊天中直接接话；完成的互动会写入手记。同一天重复同一互动不会反复增加关系奖励。

### 三款独立小游戏

| 游戏         | 实际玩法                                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 窗边棋桌     | 你执白、Echo 执黑，棋子选择与合法落点高亮、升变、将军、将死与和棋。使用 chess.js 校验全部规则；Echo 有轻松和认真两档棋力，认真档评估双方各一步后的局面。可认输、查看棋谱和再来一局。 |
| 心动翻牌     | 16 张牌、8 对图案，轮流翻两张，配对成功继续行动，全部配完按对数结算。Echo 只依据已经翻开的牌作选择；未翻开的牌面不会发送到浏览器。                                                   |
| 两人的调饮台 | 三轮点单，选择茶底、甜度、冰量和茶香，每杯最多三次试味。根据反馈调整配方，服务端计算分数；明确的少糖喜好会影响第一杯点单。                                                           |

游戏进行中暂停世界时间，避免在棋桌前触发自动作息；离开页面或重启服务后可以继续。结束未完成的翻牌或调饮不结算奖励。完成结果与共同互动统一进入长期记忆，后续聊天可以自然接续这些经历。

`pnpm test:companion` 用独立临时存档和本地对话验收记忆编辑、连续互动、棋局续玩、完整翻牌、三杯调饮和跨功能回忆，并检查桌面、手机横竖屏画面。截图在 `artifacts/companion/`，不使用真实模型或用户存档。

- 生活地图：在小家、青禾超市、星光电影院、晴川公司、转角咖啡馆和河畔公园之间出行，淡出后进入新场景。当前位置随存档保存，旧存档从小家继续。
- 家具近景：点击餐桌、沙发、工位、货架等会平滑拉近；使用“返回全景”、重置镜头或 Escape 返回。近景仍可旋转和缩放，支持减少动态效果偏好。
- 五种外出活动：买菜与便当补给、观看动态短片、办公协作、咖啡与甜点、河畔散步。每处都有独立的 3D 布景、寻路障碍和共同回忆。外出会结束未完成的活动，不结算未完成的奖励。

- Three.js 3D 小家：客厅、餐厨、榻榻米卧室与浴室。家具和 Q 版人物都是项目内生成的模型，不依赖远程美术资源。
- 两个可见角色，A* 网格寻路，行走、眨眼、坐下、躺下与部分手持物动作。
- 旋转、缩放、重置镜头；点击空地移动，点击家具选择活动。
- 8 种共同活动：做饭、吃饭、看电视、泡茶、休息、浇水、读书和整理洗漱台。
- 活动专属动作与物料：切菜、翻炒和装盘，端碗夹菜与逐渐减少的餐食，斟茶与捧杯，倾壶浇水、翻页、遥控器、擦拭和叠毛巾；加入手肘、膝盖、头部动作，以及蒸汽、水滴和呼吸起伏。
- 料理库存、饥饿与精力、可暂停和加速的游戏时间。1 倍时，1 秒现实时间对应 1 分钟游戏时间。
- Echo 根据时间和自身状态安排活动、主动说话；你可以加入她正在做的事。
- 隐藏的关系成长、情绪表达、共同经历手记和基础偏好记忆。重复活动的关系收益降低，离线不会扣亲密度。
- 推荐话题与自由文字输入，自定义称呼，桌面并排聊天、手机独立聊天视图。
- Node.js 服务端、SQLite 持久化、自定义模型连接设置。

当所有页面不再请求状态约 10 秒后，世界暂停推进。重新打开后继续；没有离线时间补算。浏览器标签页仍然打开且持续轮询时，世界会继续生活。

## 模型设置

右上角设置中填写：

| 字段         | 内容                                                 |
| ------------ | ---------------------------------------------------- |
| API Base URL | 服务商的接口前缀，例如 `https://provider.example/v1` |
| 模型名称     | 服务商提供的 model ID                                |
| API Key      | 你的密钥；不需要认证的本地服务可留空                 |

服务端在 Base URL 后追加 `/chat/completions`，支持兼容 OpenAI Chat Completions 的文本接口。聊天默认使用 SSE 流式请求，支持 `messages`、`model`、`temperature`、`max_tokens` 和 `stream`；关闭“逐段接收回复”可使用非流式模式。连接测试始终使用短的非流式请求。Base URL 不应包含 `/chat/completions`。远程服务要求 HTTPS，本机地址允许 HTTP。

保存后可点击“保存并测试”，会向你设置的模型发送一条短请求，可能产生服务商的调用费用。更换 Base URL 时不会把旧密钥自动发到新地址，需重新填写适用的密钥。留空密钥只会在地址未改变时保留旧值。

尚未配置时，界面显示“本地对话”，使用明确的规则回复和简单偏好提取；它不是完整的大语言模型。已经配置的服务调用失败时会显示错误，不会偷偷改成本地回复。真实服务的可用性需要你填入地址、模型和密钥后测试；目前自动化使用本地模拟服务验证接口协议。

## 存档与边界

- 默认数据目录为 `data/`，可以通过 `ECHO_DATA_DIR` 更换。`PORT` 可指定首选端口，`HOST` 可覆盖监听地址；设为 `127.0.0.1` 可恢复仅本机访问。
- `echo.sqlite` 保存世界、按话题保留的对话、长期记忆、互动、游戏进度、成绩与设置。长期记忆不按数量截断；模型按话题、置顶、边界和新近程度检索最多 14 条，结合最近 40 条有效聊天。最近 200 个发送编号支持跨重启的重复请求去重。
- API 密钥以 AES-256-GCM 加密存储，解密密钥在 `data/local.key`；设置接口只返回是否已设置密钥。**这不是操作系统密钥链**：拥有整个数据目录读取权限的人仍可解密。备份时应保护整个目录。
- `data/`、`.env*`、截图、依赖与构建产物均已加入 `.gitignore`。
- 服务监听所有 IPv4 网络接口，接受本机名称、回环地址和本机网卡的局域网 IP，并验证 Origin 和 JSON 请求。开发热更新与应用共用同一端口，存档、密钥和环境文件禁止通过开发静态文件服务下载。
- 局域网设备需要一次性配对，访问令牌通过 HttpOnly、SameSite Cookie 保存，数据库只保存令牌哈希；错误配对尝试有频率限制。本机回环地址无需配对。这是私人局域网方案，尚未配置公网 HTTPS 或多用户账号。若其他设备连接超时，请检查 Windows 防火墙是否允许当前私有网络中的 TCP 端口。
- 活动和作息由服务端控制。模型只负责聊天，不能绕过游戏规则执行动作。

## 接口

| 方法与路径                  | 用途                                                                               |
| --------------------------- | ---------------------------------------------------------------------------------- |
| `GET /api/state`            | 世界、活动、对话、回忆和公开关系状态                                               |
| `GET /api/settings`         | 脱敏设置                                                                           |
| `POST /api/settings`        | 保存模型连接与称呼                                                                 |
| `POST /api/settings/test`   | 测试已保存的模型                                                                   |
| `POST /api/chat`            | `{ text }`，文字交流                                                               |
| `POST /api/memory`          | `add` / `edit` / `pin` / `forget` / `save-message`，记忆管理                       |
| `POST /api/interaction`     | 牵手、拥抱、倾听、夸赞与回应                                                       |
| `POST /api/game/start`      | `{ kind, difficulty }`，开始独立小游戏                                             |
| `POST /api/game/action`     | `{ id, revision, action, ... }`，执行游戏动作；过期进度返回 409                    |
| `POST /api/activity`        | `{ kind }`，开始共同活动                                                           |
| `POST /api/activity/cancel` | 结束当前活动                                                                       |
| `POST /api/travel`          | `{ location }`，共同前往 `home` / `market` / `cinema` / `office` / `cafe` / `park` |
| `POST /api/move`            | `{ position: [x, z] }`，移动玩家                                                   |
| `POST /api/control`         | 时间控制，`speed` 可取 0、1、3                                                     |
| `POST /api/pairing`         | 在服务器本机生成一次性配对码                                                       |
| `POST /api/session`         | `{ code }`，配对局域网设备                                                         |
| `POST /api/session/logout`  | 撤销当前设备会话                                                                   |

原生 iOS 客户端已在 `ios/` 实现，使用 SwiftUI、SceneKit 和 Liquid Glass，通过上述 API 同步世界、对话、回忆和游戏进度。用 Xcode 26+ 打开 `ios/EchoHome.xcodeproj`，详见 [iOS 运行与验收说明](ios/README.md)。公网访问仍需要补充 HTTPS、多用户认证与部署方案。
